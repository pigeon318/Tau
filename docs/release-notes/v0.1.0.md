# Tau 0.1.0

The first release: a complete, usable core language with a standard library, native code generation, and the tools to
write and share programs. Tau is a small language for maths and science: braces and no semicolons, checked integers,
tensors, complex numbers, ownership instead of garbage collection, and parallel loops whose results never depend on how
many cores you have.

## Install

Download `tau-windows-x86_64.exe` (rename it to `tau.exe`) or `tau-linux-x86_64` (rename it to `tau`, `chmod +x`), put it
in a folder on your `PATH`, and run `tau --version`. After that `tau update` installs newer releases (it checks the file
against `SHA256SUMS` first). Tau compiles to native code through C when a C compiler is installed (MinGW-w64 `gcc` on
Windows, `gcc` or `clang` on Linux); without one everything runs in the interpreter, which gives the same results more
slowly. The release also has `tau-vscode-extension.vsix` for VS Code (colours, errors as you type, hover types, run and
test buttons). See `docs/GUIDE.md` for the commands and a tour of programs to run (`examples/tour/`).

## What is in it

- **The language**: structs, enums, traits and generics, closures, pattern matching, operators you can overload,
  modules and packages (`tau.toml`, path and git dependencies, `tau.lock`), `tau test`, formatted output
  (`{x:>8.3}`, `{n:#010b}`).
- **Ownership without a garbage collector**: moves, borrows, `own`, views that cannot outlive their data, `Box<T>` for
  recursive types, `Shared<T>` and `Mutex<T>` for several owners, all checked at compile time; race-free `spawn` and
  `par for`.
- **Numbers**: checked integers (an overflow is a panic, never a wrap), `f32`/`f64`, complex numbers, tensors of floats,
  complex numbers, integers and `bool` with slicing, masks and element-wise operators, linear algebra (`inv`, `det`,
  `eig`), the FFT.
- **Parallelism that is reproducible**: `par for`, `par sum`/`prod`/`min`/`max`, and tasks run on a thread pool; the output
  of a program, floating-point digits included, is the same on any number of threads.
- **Iterators**: lazy adapters (`map`, `filter`, `zip`, `enumerate`, ...) that compile to plain loops, and `for` over any
  type with a `next` method.
- **A standard library, mostly written in Tau**: `Vec` (`sort`, `insert`, `remove`, ...), strings (`split`, `trim`, `find`,
  `replace`, slicing `s[a..b]`, `parse_i64`/`parse_f64`), `Map`, `Set`, `Deque`, `Heap`, a seedable random number generator
  (`std.random.Rng`, the same numbers everywhere), `DateTime` (UTC) and clocks, files and console input.
- **Two backends that agree**: a native backend (Tau to C) and an interpreter used as the reference, checked against each
  other on every example and test, including under valgrind, UBSan and ThreadSanitizer.
- **Tools**: `tau run | check | build | test | new | add | fetch | update | clean`, a JSON diagnostics mode for editors, and
  a VS Code extension.

## What is not in it yet

`tau fmt` (a formatter), a language server (the VS Code extension uses the compiler directly), prebuilt macOS and ARM
binaries, units of measure and compile-time tensor shapes, `path`/`env`/`process` and JSON in the standard library, a
package registry, native `tau test`, and the cluster (`on`) and GPU layers. See `docs/ROADMAP.md`.

## Known limits

- Text is UTF-8 and positions are byte positions; `trim` and the character tests use ASCII rules (`uppercase` and
  `lowercase` handle all of Unicode).
- `Map` keys must have exactly the key type (`Map<String, T>` is indexed with a `String`, `Map<str, T>` with a `str`);
  `Map::remove` and `Set::remove` are O(n).
- `sort` is a heap sort (not stable). Tasks that panic do not free what they owned.
- Integer and `bool` tensor elements take 8 bytes natively.
- The interpreter prints `u128` values above the `i128` range incorrectly; native code is right.
- The Windows build is not signed, so SmartScreen may ask for confirmation the first time.
